対象ユーザーと前提

  • ITに弱い／FAX中心／スマホ不慣れ／面倒はやらない／せっかち／自分の仕事しかやらない層。
  • 想定ユーザー数: 50人以下が中心（レンジは〜20 / 〜100 / 100〜500 / 500+を想定可能）。
  • 重処理: 1つのデータから複数の帳票生成、PDF作成、巨大PDF保存/閲覧、現場調査写真の閲覧。

絶対条件

  • 取引先はSMS/LINEで入る必要なしで書類閲覧できる（共有リンク方式）。
  • 現場×相手（取引先/下請/仕入）ごとに「連絡ノート（時系列）」を持つ。
  • 送信はOS共有シート中心（LINE/Gmail/メール/SMSなど自由）。
  • 既存の予定表/取引先/日報/見積/CSV機能は壊さない。
  • UI文言は短い動詞・責めない文言で監査。
  • 体感0遅延（入力が止まらない・待たせない・後で完了）。

必須機能要件（PR）

PR-1: 連絡ノート

  • Thread = 現場 × 相手（取引先/下請/仕入）。
  • 時系列イベント: 受領/送信/写真/メモ/工程/日報/訂正/取り消し。
  • 送る: OS共有シートでLINE/Gmail/メール/SMSへ。
  • もらう: 外部アプリ → 共有 → 本アプリ（現場・相手の2択）。
  • 共有リンク: 期限（デフォルト7日）、即時失効、閲覧ログ（「見た記録」以外の表現は禁止）。

PR-2: 外注区分フィルター

  • マスター/CSVに「区分」列を追加（互換は欠損時にその他）。
  • 機械・資材と同様のフィルターと検索。

PR-3: 工種×講習の累計表示

  • 期間切替（当月/年度/全期間）。
  • 実施回数/実施人数の累計。

PR-4: 日報累計表示

  • 人工/機械/資材/外注/原価の累計。
  • 今日分の差分表示。

PR-5: 迷いゼロ導線

  • 3画面原則: 今日 / 連絡 / 日報・写真。
  • 7ステップ: 日程 → 作業員 → 機械 → 資材 → 外注 → 確認 → 提出。
  • 進捗バー、未入力の可視化、次にやること表示。

PR-6: 画質/品質

  • 写真はプレビュー先行＋原本をバックグラウンド送信。
  • PDF/画像の可読性基準を明記（A4で文字高さ12px以上）。
  • 通信が弱い現場で止まらない（オフラインキュー）。

エンジニアリング・ガードレール

  • iOS/Android 同時リリース。
  • 対応OSは広く、体感0と安定性を壊す下限は許可しない。
  • サーバ中心、ローカルファーストは同期キューで補完。
  • 重い処理（PDF生成/OCR/サムネ生成）は非同期ジョブ。
  • 添付はbase64禁止、保存してURL返却。
  • APIは冪等（Idempotency-Key）。
  • レート制限、監査ログ、trace_idを標準化。
