専門家構成（計200名）

8分野×25名で構成。議論は分野横断で実施し、最終決定は全分野の合意を条件とする。

分野人数主な観点
Product / PM25価値、優先順位、段階リリース
UX / アクセシビリティ25説明なし操作、可読性、誤操作防止
Backend / データ25整合性、追跡可能性、互換性
Frontend / モバイル253タップ完了、速度、オフライン耐性
QA / テスト設計25再現性、受け入れ基準、回帰防止
Security25共有リンク保護、権限、監査ログ
DevOps / SRE25運用性、障害時復旧、監視
Legal / Compliance25建設業法、個人情報、証跡要件

激論の争点と合意した採用案

  • 争点1: 機能数 vs 迷わなさ → 初期画面は「今日」「連絡」「日報」3導線のみ表示。
  • 争点2: 速さ vs 正確性 → 先に保存、重処理は非同期。提出/送信の証跡は必ず残す。
  • 争点3: 取引先導線 → SMS/LINEで入る必要なしの共有リンク方式（PIN/期限/失効）。
  • 争点4: 既存運用との互換 → 既存CSVは非破壊拡張、外注区分を追加して整合。
  • 争点5: 通知疲れ → 緊急/重要/参考の3段階、同一案件は集約配信。

全員称賛で採択された実行プロンプト

Prompt v1.0

「現場担当・取引先・事務の3者が、説明書なしで ①予定確認 ②連絡共有 ③日報提出 を完了できるUIを実装せよ。 受入条件は、主要操作3タップ以内、文字は読みやすい大きさ、誤操作時は復旧導線あり、 共有リンクはPIN/期限/失効/閲覧ログを備えること。重処理は非同期化し体感待ち時間を最小化し、 既存CSV連携は壊さない。最終的に、異業種テスターを含む100名の無説明テストで全員成功を確認すること。」

プロンプト実行結果（要約）

  • UIは「今日 / 連絡 / 日報」中心の固定導線で統一。
  • 連絡は共有シート経由、証跡は見た記録と送信履歴で追跡可能。
  • 共有リンクは安全制御（PIN/期限/失効）を仕様化。
  • 検証は100名の業種別テスト計画に接続（詳細はテスト/検証ページ）。
