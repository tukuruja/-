推奨構成（実装と運用の最小コスト）

  • フロント: React Native（iOS/Android同時）＋PWA（共有リンク閲覧）。
  • API: Node.js + TypeScript + Fastify（REST + OpenAPI）。
  • PDF/OCR: Python（index.py）で非同期ジョブ。
  • CSV/マスター: Google Apps Script（gas.js）で既存シート連携。
  • DB: PostgreSQL（Cloud SQL / RDS）。
  • ストレージ: S3互換（GCS/AWS）。
  • ジョブ: Cloud Tasks / SQS。
  • 監視: OpenTelemetry + Metrics + Trace ID。

PDF base64 → 保存＋リンク

方針 APIがbase64でPDFを返さず、ストレージに保存し署名URLを返す。
1. PDF生成（Python index.py） 2. ストレージへ保存（S3/GCS） 3. ShareLinkを作成 4. 共有リンクURLを返却 5. 閲覧時は短期署名URLでリダイレクト

オフライン同期・競合ルール

  • ローカルキューへ保存 → 後で自動送信。
  • client_event_idで重複排除。
  • サーバは追記のみ、競合はDUPLICATE/NEEDS_RETRY/REJECTEDで返す。

画像/書類の画質パイプライン

  • 撮影直後にプレビュー生成（端末内）。
  • 原本はバックグラウンド送信。
  • PDFは先頭ページを先に返す。
  • 通信断はキューに残して再送。

外部API連携（拡張）

  • 気象庁API: 雨天時の工程リスケジュール提案。
  • Google Maps API: 現場位置/測点の記録。
  • Vision API: 黒板OCRと自動分類。
  • Speech-to-Text: 音声入力のテキスト化。

環境の答え（質問への結論）

現状の作りたいものを耐える構成は、モバイルはReact Native、APIはNode.js、PDF/OCRはPython、CSV/マスターはGASのハイブリッドが最短。

デプロイ先は、フロントと共有ページはVercel、APIとジョブはCloud Run/Functions、DBはCloud SQL、ストレージはGCS/AWSが最適。

実装は「止めない・待たせない・後で完了」を最優先
